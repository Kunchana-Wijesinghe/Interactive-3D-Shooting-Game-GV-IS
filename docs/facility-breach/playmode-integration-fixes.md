# Prototype Play Mode integration fixes

Validation: Unity 6000.6.2f1, built-in rendering, real Play Mode in a full isolated copy of `Assets/Scenes/Prototype.unity`. The user's open Editor was not interrupted. **112 checks passed, zero C# compilation errors, and no unexpected Console errors.** Result is recorded in `evidence/playmode-integration-results.txt`. This report supersedes earlier blanket completion claims for the behaviors below.

The legacy foundation harness now looks up the renamed public shooting entry point.

## Diagnostics

Enable **Development Diagnostics** on `FB_Gameplay` in a development session. `[FB gameplay]` traces cover mission/input acceptance, E candidate/distance/rejection, camera/muzzle ray and collider/layer, receiver and HP, SH state/hearing budget, and navigation goal/status/failure. Calls compile out of normal release builds. They are disabled in the committed scene by default.

## Preservation and test environment

Fresh pre-fix hashes verify 114 protected/generated-environment files unchanged, including all 86 protected files (including `Assets/Perera.meta`). Only MonoBehaviour `7000000003` changes in the 5,415-record Prototype scene, assigning ten visual prefabs and the separate scoped navigation asset. Removing those added assignments restores the exact pre-fix scene SHA-256. See `evidence/playmode-integration-preservation.json`. No world generator ran, no authored environment transform/light/door/barricade changed, and existing navigation assets were not overwritten. User's untracked `ProjectSettings/PackageManagerSettings.asset` is excluded.

The isolated copy initially raised `UnityEditor.Search.SearchDatabase` startup exceptions unrelated to gameplay. Editor search startup indexing was disabled in the temporary copy's `UserSettings/Search.settings` only; production assets, package manifest, and user preferences were unchanged. These failures are not counted as successful runs.

## Manual acceptance steps

1. Open Prototype, allow script/asset import, and click Start Mission. Apply the light-gizmo menu if needed. Confirm an identifiable first-person gun and all four colored robot models.
2. Walk to the Storage Ammo2 station and safe edge near the waste Ammo3 station. Aim near each pickup, press E, fire, and swap back. Check magazine persistence, a single E prompt, no collection through solids, and safe reload cancellation.
3. Hit isolated PG/SH/CD/FL with Ammo1. Count confirmed HUD HP reductions to 6/8/9/7; distinguish blocked shots. Check fallen presentation, state light off, sensing/attacks stopped, and revival after 30 gameplay seconds only at a safe post. Repeat the automated Ammo2/3 damage checks for 15/20 HP in rendered gameplay.
4. Shoot each marked crate once, collect with E, and reload with R. At reserve 200 verify pickup remains; consume/reload a round, collect partially, and verify remainder persists until the 15-second restoration deadline.
5. Observe temporary PG patrol and visible-player detection; hide behind a wall, fire near SH, move away unseen, and confirm emitted-origin investigation, search then patrol. Verify closed-door attenuation and navigation around all six movable barricades in rendered gameplay.
6. Pause during reload/investigation, resume, then restart. Check no duplicated camera/agents/listener and no Console errors. CD/FL cover/flank behavior is absent and must not be signed off as complete.

## Reproduce automated checks

Use a full copy of the project when the main Editor is open. Launch Unity with `-batchmode -nographics -projectPath <copy> -executeMethod FacilityBreach.Editor.PlayModeIntegrationValidation.Run -logFile <log>` (no `-quit`; runner exits after Play Mode). Results appear at the copy root as `integration-playmode-passed.txt` or `integration-playmode-failed.txt`. This is programmatic Play Mode, using the same gameplay API reached by E/fire, with real physics and navigation; it does not simulate keyboard/mouse or verify rendered pixels.
